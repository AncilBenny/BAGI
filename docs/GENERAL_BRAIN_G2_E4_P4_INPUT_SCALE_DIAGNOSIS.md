## An upstream source-level mechanism, not a new RL algorithm

Farama MiniGrid v3.2.0 public `image` encodes **(object ID, color ID, state ID)** in a `(7,7,3)` tensor. See source `minigrid/core/constants.py`, upstream wrapper `ImgObsWrapper`, and its available `OneHotPartialObsWrapper` in `minigrid/wrappers.py` (Apache-2.0). Object IDs include `unseen=0`, `wall=2`, `goal=8`, `agent=10`. **These are categorical IDs, not pixel brightness.** The registered BAGI runner applies `ImgObsWrapper` followed by Gymnasium `FlattenObservation` and feeds a **147-element uint8 Box** into upstream Stable-Baselines3 v2.9.0 `MlpPolicy` with Tanh. Verified exact SB3 v2.9.0 `preprocessing.py`: `is_image_space` applies to recognized 3-D image Boxes; `preprocess_obs` returns `obs.float()` unscaled for other Box inputs, and divides by 255 only for recognized images. Flattening therefore bypasses SB3's automatic image scaling. SB3 is operating as documented; the BAGI observation adapter created the raw unnormalized categorical input.

## Single-variable offline numerical test: magnitudes, not architecture

Both original P1 and P3 ZIP SHA256 values were reverified. Use only `numpy.load(..., allow_pickle=False)`. Take **all unique actual public pre-action observations** from previously completed P3 live + stale native traces (48 unique seed17; 46 unique seed29), independently for each original seed. Reuse both unchanged **initialized/untrained** and **trained** P1 actor weight arrays. At first and second Tanh hidden layers, compute mean fractions `abs(tanh(preactivation)) > 0.95` and mean derivative `mean(1 - tanh(preactivation)^2)`. Then, *without any model re-training, PPO action sampling or simulator calls*, repeat just the numerical forward pass on **the exact same observations divided by 10**. The factor 10 is the published highest object-ID value, not a hyperparameter selected from heldout rewards. Inputs remain 147 values, same network and parameters; only scale changes.

| Seed/model state | First-layer saturation RAW | First-layer saturation public /10 | Mean first-layer Tanh derivative RAW | Derivative /10 |
|---|---:|---:|---:|---:|
| 17, untrained | 64.9740% | 0.0000% | 0.1860 | 0.8810 |
| 17, trained | 81.2500% | 0.0000% | 0.0996 | 0.8254 |
| 29, untrained | 65.4212% | 0.0000% | 0.1917 | 0.8776 |
| 29, trained | 74.8302% | 0.0000% | 0.1252 | 0.8416 |

The **second** hidden layer also showed substantial trained-network saturation under raw input: **50.4883%** (seed17) and **41.7799%** (seed29); under input /10, only **0.358% / 0.917%**. This is a controlled *activation* result, not a controlled *learning* result. The raw codes have values 0..8 in the archived observations; the largest official object code is 10. Early input saturation is already present before policy training; additional saturation occurs during PPO training. Reducing the input magnitude to at most 0.8 on these data removes the observed first-layer saturation with the SAME frozen weights. This is causal evidence that large unnormalized input values produce the saturation in this numerical setting, not proof that it independently caused poor live-feedback usage.

**Important limits:** (1) the observations were from *previously examined TEST trajectories*, not an untouched development dataset; use them for this retrospective diagnosis only, NEVER to score/train/select a modified policy on old TEST seeds. (2) Scaling the input of weights that were trained on the old scale changes their meaning; DO NOT claim that the original frozen actor would improve if rescaled post hoc. (3) Tanh saturation does not imply all visual information is lost; derivatives and categorical output still change. (4) It does not yet prove that normalization (or one-hot encoding) improves real learned navigation, causal skill, memory, or transfer.
