## Open question and falsifiable alternatives

**Can standard, public-observation-only PPO learn to complete goals on genuinely different MiniGrid reset layouts within a small fixed interaction budget, beyond untrained network and random controls?** Alternative: sparse reward, reactive partial observation, or insufficient interactions yield no independent competence. Empty-Random is an easier navigation control; DoorKey-5x5 is a harder key/door/goal sequential task. These are **two related MiniGrid families, not unrelated domains**. No XLand BLUE-specific algorithm logic is permitted. Memory, reusable skill learning, cross-domain transfer, retention and belief learning remain **untested** by this study.

## Frozen source, seeds, controls and native resource ceiling

- Only **two preregistered tasks**: `MiniGrid-Empty-Random-6x6-v0` and `MiniGrid-DoorKey-5x5-v0`; two model seeds `17,29`. No further benchmark additions or post-result hyperparameter search. The four previously validated tasks are not all trained; this is a bounded learnability gate before memory/transfer.
- For each task/model seed, train one **upstream SB3 PPO `MlpPolicy`** for exactly **16,384 real native TRAIN actions**, 4 models = **65,536 TRAIN**. Use native sparse rewards only; public flattened 7×7×3 local image; native 7-action space. No full grid, agent absolute position, pocket/hidden flags, task-specific scripted reward, privileged events, intrinsic bonus, expert labels or world-model imagination enter policy inputs or training rewards. Fixed PPO: CPU, single environment, `n_steps=128`, `batch_size=64`, `n_epochs=2`, `gamma=0.99`, `learning_rate=3e-4`, `ent_coef=0.01`, policy/value MLP widths `[64,64]`, no checkpoint loading. Log exact model training steps, native steps, training wall time, native goal completions and reset-layout diversity.
- **Disjoint TRAIN reset stream** is explicit on every episode: `1,000,000 + task_index×200,000 + model_index×100,000 + reset_counter` (task index in listed order, model index `17→0`, `29→1`). The wrapper discards any SB3-provided reset seed and sets the preregistered seed; it logs all actual reset seeds. Streams cannot overlap at this bounded budget. Training observations/rewards remain public/native only. All G2-E4-P0 diagnostic seeds `21000..21015` and previous G2-E3 TEST seeds are excluded from training and TEST.
- **Untouched TEST seeds** `26000..26009` (ten starts per task/seed) were reserved in G2-E4-P0 and never used in its diagnostic. Each trained policy is frozen after training; compare **three arms on exactly the same TEST starts**: (a) uniform random actions from an independent fixed NumPy RNG, (b) an identically initialized **untrained** PPO network whose initial parameters are verified tensor-for-tensor, (c) the trained PPO network. Both network arms use deterministic `predict`, with no recurrent state. Controls use **zero TRAIN actions** by definition and **matched native TEST starts/episode caps**, not a misleading claim of equal TRAIN exposure. No test result influences optimizer or task selection.
- Native TEST episode cap is upstream **144 actions** for Empty-Random-6x6 and **250** for DoorKey-5x5; early goal/time-limit termination stops the episode. Max TEST `2 model seeds × 3 arms × 10 starts × (144+250)=23,640`, total **≤89,176 actual native actions** including all training. No hidden uncounted `env.step` calls, probes, teacher calls, discarded counterfactuals, or heldout test-driven reruns. The code checks action/reward validity, logs actual step totals, saves per-step PUBLIC pre-action observations, actual actions, native rewards and done flags as **numeric-only NPZ with `allow_pickle=False` compatibility**; includes numeric model state arrays for reproducible offline audit. Evaluator-only full-grid + agent-start SHA256 hashes are used strictly to verify reset diversity and arm parity; they NEVER feed policy/action/reward selection.
- Each task/model seed must show at least **8 distinct physical TEST starts out of 10**; if not, the corresponding result is **not eligible** for a generalization claim, regardless of reward. This is verified from native TEST reset fingerprints in the actual evaluation, not assumed from G2-E4-P0's other seeds. Report each model seed separately, native successes and native reward separately, random/untrained/trained real evaluation actions and paired outcomes.

## Preregistered primary success, secondary diagnostic and STOP

- **Primary Empty-Random navigation competence gate:** BOTH model seeds must (i) have ≥1 rewarded native TRAIN goal, (ii) pass ≥8/10 physical TEST reset diversity, (iii) achieve **≥5/10** independent frozen deterministic TEST native goals, and (iv) exceed **each** random and untrained control by **≥3/10** native goals on their matched starts. Only then say a standard learner demonstrated a modest, task-specific, variable-layout navigation competence. This is not task-independent intelligence or memory.
- **Secondary DoorKey causal task gate:** BOTH model seeds must (i) have ≥1 rewarded TRAIN goal, (ii) pass physical diversity, (iii) reach **≥2/10** frozen TEST goals, and (iv) exceed each control by ≥2/10. This is a deliberately weaker feasibility diagnostic; do not promote task-independent causal reasoning or cross-domain transfer from it. Native goal reward plus termination is the criterion, not picking up a key alone.
- **FAIL/STOP** if primary gate fails: no promotion, no test-driven hyperparameter adjustments, no extra TEST layouts, no scaling/recurrent model merely because PPO failed. Investigate TRAIN reward coverage, action distribution and budget adequacy using existing artifact before a *separately preregistered* new experiment. If the primary passes, a separate memory and eventual retention/transfer gate must be registered on fresh, independent conditions. Report a causal-task failure even if navigation passes. No user-facing claims until native artifacts and actual action counts are audited.
