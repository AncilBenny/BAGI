## Prior measured evidence and open question

M8 source `1cee0b4d0365acd1cb0ad852b2e4aed3f3e46337`, research run [43000306359](https://github.com/AncilBenny/BAGI/actions/runs/43000306359), artifact ID `13847165267` (ZIP SHA256 `b4d3d189bb99f88493235d1373fa9e87e1c4971532183d3502b613290a8159e8`) completed four fresh PPO fits, 524288 native training actions and 16384 optimizer updates. Entropy-coefficient 0.02 failed against coefficient 0.0: 0/72 sampled verified full DoorKey goals versus standard 1/72; deterministic 0/24 in both arms. Physical key pickups occurred, door opening was very rare, and no robust task competence was established. The frozen M7 evaluation showed a single physically verified sampled complete goal, without reproducible evidence across seeds. Historic M3 recurrent PPO was weak on its separate memory benchmark. None of these findings establishes whether *recurrent memory on DoorKey with continuing native episodes* helps action sequencing beyond four preceding executed actions.

**Primary source and reused implementation:** Schulman et al. (2017) PPO https://arxiv.org/abs/1707.06347 ; Kaelbling, Littman & Cassandra (1998) POMDPs https://doi.org/10.1016/S0004-3702(98)00023-X ; maintained SB3-Contrib v2.9.0 `RecurrentPPO/MlpLstmPolicy` https://sb3-contrib.readthedocs.io/en/master/modules/ppo_recurrent.html (including explicitly carried `lstm_states` and `episode_start` at prediction), maintained SB3 PPO v2.9.0 https://stable-baselines3.readthedocs.io/en/master/modules/ppo.html and official Farama MiniGrid DoorKey https://minigrid.farama.org/main/environments/minigrid/DoorKeyEnv/ . Already integrated and dependency-pinned in BAGI. Both upstream libraries MIT-licensed. The exact RecurrentPPO CPU implementation is reused; there is no new loss, hand-scripted solution, oracle action, teacher or task-specific reward shaping.

**Open scientific question H-M9:** at matched native training interactions, optimizer-step schedule, full 256-action native episode continuity, public observations and actually executed 4-action history, does the maintained recurrent PPO learn physically verified key→locked-door opening→goal sequences on unseen DoorKey layouts better than standard PPO? No claim of task-independent continual learning from one within-task pilot. Recurrent and reactive models differ in internal hidden-state machinery, parameter count and gradient path; record them, do NOT claim a perfectly parameter-matched one-variable causal comparison.

## Frozen methods, resources and independent splits

- Two arms `reactive_history` (SB3 `PPO("MlpPolicy")`) and `recurrent_history` (SB3-Contrib `RecurrentPPO("MlpLstmPolicy")`, one LSTM layer, hidden size 32). Both use BAGI's existing public `PublicGoalActions` 243-dimensional local MiniGrid observation + mission token hashing + four **actually executed** previous actions; never private `info`, carried inventory, map, door lock or reward shaping as policy features. Native seven actions, DoorKey8x8, TimeLimit256, native sparse terminal success reward.
- **Four fresh fits:** independent *model initialization* seeds **151, 167**, both arms each. One continuous `learn(total_timesteps=131072, reset_num_timesteps=False)` per fit; no extra reset between 128-step PPO rollouts. SB3/Contrib policy `net_arch pi/vf=[32]`, recurrent `lstm_hidden_size=32, n_lstm_layers=1`, otherwise default PPO gamma/GAE/clip/learning-rate/entropy coefficient0.0/optimization, `n_steps=128, batch_size=64, n_epochs=2`, CPU. Each fit target **131072 genuine native training interactions** and expected **4096 intercepted `optimizer.step` calls**, total design **524288 interactions and 16384 optimizer calls**, count actual not assume. These are comparison exposures, NOT global training limits or daily caps. Per-arm training environment native reset seed stream `1000000 + model_seed*500000 + reset_index`, independent of all heldout/test seeds; record SHA of each actual stream. Policy hidden state must survive PPO block boundaries and reset only on native episode boundaries.
- Six *monitor* layouts **117001..117006**, evaluate before and after training for each model, deterministic closed-loop; monitor results never used for model selection or adjusting the registered comparison.
- Final *independent* DoorKey layouts **118001..118012**, disjoint from M1–M8 final/monitor layouts. Access ONLY after all four models pass full native action counts, exact counted optimizer updates, no interrupted incomplete episode resets, >=256 observed episode length, numeric-only checkpoint export and seed integrity. On each model run 12 layouts deterministic once, then sampled action selection 3 preseeded RNG repetitions per layout, using outcome-independent seeds determined by arm/model/layout/repeat indices. A repeat on a fixed layout is NOT an independent new layout. Recurrent evaluations MUST carry `lstm_states` through actual steps and set `episode_start=True` only on the initial step of each native episode; reactive action selection uses identical observation/history. Per run action histogram, native steps/resets, rewards, termination, actual evaluator-only key pickup, locked→open door and complete physical goal are recorded.
- Primary pilot gate **H-M9 PASS** iff pooled recurrent sampled full physical completions exceed reactive sampled by **at least 4/72** and **both independently initialized recurrent models have ≥1 physical complete goal** on the new independent layouts, after ALL training integrity prechecks pass. Report reward-only success and deterministic goals separately, per-model variance and repeated-layout dependence. If any requirement fails, H-M9 FAILS; positive train reward or unverified action attempts do not count as full competence.
- Secondary: physically verified pickup and opening *episode* counts, events per episode, actual native action frequencies (including ineffective `done`), success over true independent layouts, training reward goal terminations, per-model parameter totals, training resets, runtime and numerical checkpoint provenance. Holdouts are never used to tune hyperparameters, select stochastic RNG outcomes, or justify posthoc thresholds.
