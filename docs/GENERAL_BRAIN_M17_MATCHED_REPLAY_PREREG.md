# BAGI M17 — exposure-matched source replay versus extra target-only labels

**2026-11-12 UTC preregistration, before any M17 actions, fitting, monitoring or final evaluation.** M16's existing result on new independent DoorKey layouts showed source replay target success 39/48 versus naive sequential BC 27/48; however both preregistered M16 transfer and retention gates FAILED. The +12 result was exploratory and source replay used extra cached labels. M17 tests whether the *source identity* of those additional labels matters, compared with the same number of extra **target-domain** training labels. Do not rerun or tune on M16 FINAL, M15 FINAL, or any older independent test layouts.

## Evidence and reuse decision

- Primary paper: Rolnick, Ahuja, Schwarz, Lillicrap & Wayne (NeurIPS 2019), *Experience Replay for Continual Learning*, https://proceedings.neurips.cc/paper/2019/hash/fa7cdfad1a5aaf8370ebeda47a1ff1c3-Abstract.html . CLEAR demonstrates replay with cloning in continual RL, but does not establish BAGI's specific source-domain causal effect or learned physical success under matched label exposure.
- Maintained benchmark: Farama MiniGrid DoorKey native `MiniGrid-DoorKey-6x6-v0` and `MiniGrid-DoorKey-8x8-v0`, https://minigrid.farama.org/main/environments/minigrid/DoorKeyEnv/ . DoorKey requires real key pickup, effective door opening, and goal arrival. Reward is separately reported but is not sufficient to claim the physical action chain.
- Established implementation: reuse BAGI's tested `BCPolicy`, legal 89-feature public observation/action-memory encoder and numeric-only checkpoint writer from M15; M14 public scripted training-demonstration policy; M10 independent native physical auditor; and M16 sequential PyTorch CE/Adam training with explicit optimizer and additional-example accounting. No novel learning optimizer or replay algorithm is claimed. The actor's pickup-evidence bit and reference teacher are HAND-SPECIFIED. Public mission/direction/front tile and own executed-action memory are the only learned-policy inputs; no private positions, oracle or auditor flags reach the policy. This is experiment replication/control and within-family evaluation, NOT cross-domain or task-independent continual learning.
- Distinguishing missing fact: M16 did not include an **exposure-matched target-only additional-example control**. Thus +12 goals might reflect added labels, source identity or stochastic actor differences. M17 changes the origin of the additional labels while controlling target data, optimizer updates and presentations.

## Frozen acquisition, training and controls

- Fresh SOURCE TRAIN: 48 genuinely executed public-controller demonstration episodes DoorKey6×6 on seeds **251001–251048**. Fresh TARGET TRAIN: 48 actual episodes DoorKey8×8 seeds **261001–261048**. Source/target numeric training sets captured ONCE and reused by every new fit. Each episode records actual native action histogram, action SHA256, public input vectors, independent physical key/door/goal evidence and effective native action counts. Training traces numeric-only NPZ with digest, ignored under `runs/`. Do not relabel cached M16 models or data as newly collected.
- Independent model initialization seeds **601, 607, 613, 619**. Each starts from the same architecture and initialization within that seed. Existing PyTorch two-layer public MLP, hidden64, 7 native logits. Four TARGET-stage arms plus one frozen-source arm per model seed: (1) `source` — train SOURCE only, freeze; (2) `scratch` — train TARGET only from initial weights; (3) `naive` — train SOURCE then TARGET normally; (4) `extra_target` — train SOURCE then TARGET, each TARGET update mixing CE on its minibatch and CE on exactly one extra *cached target* sample per primary minibatch element, 0.5+0.5 loss weighting; (5) `source_replay` — same SOURCE initialization and TARGET updates, but that second CE uses one extra *cached old SOURCE* sample per element instead. All target-stage arms have identical TARGET dataset, minibatch order and target optimizer step count; both extra-label arms have EXACTLY equal additional cached label presentations and optimizer step counts. Source stage has its own accounted optimizer steps. Optional extra target labels are extra *presentations*, not extra real simulator actions. Expected updated counts are measured, not inferred solely from settings.
- Ten epochs per fitting stage, batch128, Adam lr0.003, unchanged M15/M16 feature contract. There are **20 fresh numeric model fits** (4 source fits and 16 target fits), not 20 separately collected training datasets. Record actual optimizer calls, target and extra cached label exposures per arm, model parameters, SHA256 numeric checkpoints, exact source/config/library versions, and actual runtime. These sample/epoch choices are matched preregistered scientific settings, not imposed platform-wide training ceilings.
- TRAIN-only monitor layouts: 6×6 **252001–252012**, 8×8 **262001–262012**, 12 per size. Independently reserved final: 6×6 **253001–253032**, 8×8 **263001–263032**, 32 per size. The FIVE learned arms × FOUR model seeds plus scripted teacher and uniform random = 22 evaluation conditions per task size; **528 monitor** and **1,408 independent final native episodes**, all actor modes evaluated on the same new layout sets. Models are frozen before monitor; no tuning or model selection on final outcomes. Use common random-number policy sampling for a given layout/model seed across learned arms, but policies generate different action trajectories, and no matched-action causal claim is made.
- For each task, condition and model seed: actual native actions; full seven-action histograms; genuine key pickups; effective door openings, valid toggle attempts/opportunities; physically audited key→door→rewarded goal completion; native reward separately; and episode-level evidence. Preserve any partial run with provenance and declare the independent final stream opened only if actually evaluated.

## Preregistered success decision and limitations

- **Primary gate**: pooled new 8×8 independent physically verified goals for `source_replay` minus `extra_target` is **at least +12 goals out of 128** (4 model seeds×32 untouched target layouts), AND `source_replay` has a positive per-model-seed 8×8 goal difference in **at least 3 of 4** model seeds. This tests source identity at matched extra label exposure. Meeting the gate would be within-family evidence, not autonomous lifelong or cross-domain generalization. Report actual pooled numbers, each seed's difference, and uncertainty.
- **Secondary (descriptive, not additional passes)**: compare both extra-label arms against `naive` and `scratch` on 8×8, and source-only vs naive/extra_target/source_replay retention on 6×6. Preserve failed gates and any apparent target-only gains, and do not read a lack of source forgetting as catastrophic retention failure. A mechanistic attribution still requires work because different labels imply different optimization gradients and trajectories, even if count-matched. Model seed n=4 remains limited.
- If primary fails, do NOT retune based on these final layouts; plan a new hypothesis/independent study only if an unresolved question remains. Do not count the earlier M16 post-hoc +12 as an M17 independent success.
