# BAGI-M5 — preregistered public-goal continual task retention pilot

**Predeclared 2026-11-11 UTC, AFTER inspecting M4 and BEFORE any M5 fit, public simulator action, optimizer update or held-out outcome. Proposal/registered hypothesis only.**

## Open BAGI gap, primary research, maintained reuse

M3 independently failed to reproduce an exploratory recurrent-memory transfer ranking; M4's frozen-policy sampled-action hypothesis also failed across the two independently initialized recurrent policies. M4 did show action-history PPO held-out deterministic size13 success for both old model seeds (each 9/12 on entirely new layouts); this is **not** evidence of persistent learning of multiple tasks. The next missing property is learning an additional, genuinely different goal requiring causal object interactions while preserving competence on the previous goal, using only publicly available observations and actually executed actions.

- Rolnick et al., *Experience Replay for Continual Learning*, NeurIPS 2019, https://papers.neurips.cc/paper_files/paper/2019/hash/fa7cdfad1a5aaf8370ebeda47a1ff1c3-Abstract.html . Continual RL requires both plasticity and retention; CLEAR uses off-policy replay and behavior cloning corrections. **Do not** claim that simply replaying stored off-policy samples in on-policy PPO is valid, or that interleaved fresh rollouts reproduce CLEAR.
- Ni, Eysenbach and Salakhutdinov, ICML 2022, https://proceedings.mlr.press/v162/ni22a.html . Strong memory baselines require fair public-observation controls and independent evaluation.
- Maintained upstream Stable-Baselines3 PPO / set_env and learn, https://stable-baselines3.readthedocs.io/en/master/modules/ppo.html and https://github.com/DLR-RM/stable-baselines3/blob/master/stable_baselines3/common/base_class.py . Reuse pinned stable-baselines3==2.9.0; train on fresh real rollouts and keep exact optimizer accounting. Never port an unvalidated new RL optimizer.
- Official Farama MiniGrid Memory (https://minigrid.farama.org/main/environments/minigrid/MemoryEnv/) and DoorKey (https://minigrid.farama.org/main/environments/minigrid/DoorKeyEnv/). The latter needs a physical key pickup, door unlock/open and native goal reach; reward by itself is insufficient to claim those intermediate effects. Both tasks use Discrete(7) but differ in objectives and mechanism.

**Contribution type:** an integration/evaluation of maintained PPO with a public-mission observation adapter and independently measured continual retention, not a novel learning algorithm or an AGI claim. Workshop and XLand remain external diagnostics, not substituted for independent goal learning evidence.

## Frozen H-M5 and matched baselines

**H-M5:** At matched per-task native training experience and matched PPO optimizer settings, alternating fresh *on-policy* experience between an observation-only memory task and a causal manipulation/navigation task preserves more MemoryS7 held-out goal completions after both tasks have been learned than blocked task-by-task experience, **without sacrificing meaningful DoorKey competence**.

- Target tasks: MiniGrid-MemoryS7-v0 and MiniGrid-DoorKey-8x8-v0. Reuse established reactive/action-history PPO, selecting **action4** as the simple recent transfer control. Do not add a recurrent architecture to explain away its failed M3/M4 rankings. Seed freshly initialized policies **71 and 83**, distinct from previous M1–M4 model seeds; use same architecture/parameter count and public observation contract for both schedules.
- Public policy inputs: local image, a fixed dimension encoding of the *publicly presented mission text* (no simulator internals, evaluator state, key inventory, agent pocket, hidden layout, object ID oracle, or privileged task outcome) and four actually executed previous actions. Any goal-text encoding must be generic rather than BLUE-specific or an undocumented hand-coded action phase; test reset/action provenance and identical policy observation/action shapes in both tasks. A separately instrumented EVALUATOR may inspect native key carried and door transition state to label physical effects; those labels must never reach the acting policy.
- Main matched conditions: (A) **blocked** on-policy schedule, 65536 native Memory training actions followed by 65536 DoorKey native actions; (B) **interleaved** on-policy schedule, 65536 native Memory actions plus 65536 native DoorKey actions alternated in registered 128-action PPO rollout blocks. Both consume **131072 native training actions per model** if completely executed and exactly the same exposure to each task. Use identical fresh seeds and task-specific training-layout distributions across schedules, with no evaluation feedback controlling task exposure. To make optimizer and resetting comparable, use the same upstream PPO rollout128/batch64/epochs2/CPU and the same per-block learn/reset mechanics in BOTH schedules.
- Task-only sanity controls: a fresh Memory-only PPO and a fresh DoorKey-only PPO per seed, each exposed to the corresponding 65536 native actions under the exact same architecture and optimizer settings, without task switches. These are controls, not a license to compare raw training reward as independent held-out competence.
- Per-study matched initial comparison exposure if eight planned fits finish: 4 joint fits x 131072 + 4 task-only fits x 65536 = **786432 native training interactions**. With unchanged two-epoch PPO minibatches, expected 24576 optimizer.step calls; **measure actual calls**, real executed actions/resets, rollout and update provenance, time, seeds, native positive reward AND termination and intermediate physical effects. These are registered experimental exposures, NOT custom daily quotas, global train ceilings, platform runtime caps or restrictions on scientifically justified later fresh fits. If extension is warranted by TRAIN-only learning curves, preregister a fair matched continuation with untouched evaluation splits and retain this initial study unchanged.
- Native evaluation: for each model and each task use new independent untouched seeds **MemoryS7 102001–102012, DoorKey8x8 103001–103012**; max 256 real native actions per evaluation episode with identical conditions. Hold them out from fitting, schedule changes, architecture selection and model selection. Separate training-monitor seeds **104001–104006 and 105001–105006**, not part of final held-out denominators; lock training schedules before either final split is scored.
- Record untrained, after each registered training phase (using monitor seeds for adaptation diagnostics), and final independent held-out reward+terminal navigation success on both tasks. For DoorKey separately record evaluator-only physically **executed key pickup, door opening/unlock, and goal reach**; do not infer physical interaction from positive reward or attempted pickup/toggle. The policy must not read evaluator private information. Report final per-seed task success, learning curves versus actual native actions, unique attempted task episodes, forgetting/retention on Memory, forward transfer relative to DoorKey-only, runtime/optimizer updates and native goal versus physically confirmed effects.

## Decision and uncertainty

Primary descriptive pilot gate on final independent episodes: the interleaved schedule achieves **at least 4/24 more MemoryS7 goal completions than blocked** across both model seeds, loses **no more than 2/24 DoorKey rewarded goal completions** relative to blocked, and BOTH interleaved trained seeds complete at least one held-out Memory goal and one held-out physically verified DoorKey goal. Because sample sizes are small, report exact per-seed counts, layout-level uncertainty and episode trajectories; even a pass is not proof of task-independent general intelligence.

If DoorKey physical key/door changes cannot be verified without privileged data entering the learner, HOLD the physical success claim; fix the evaluator boundary first. If public observation shapes or task goals cannot be made compatible without hardcoded task-specific policy phases, HOLD training and test the adapter rather than silently changing the hypothesis. If both policies fail to learn DoorKey in initial matched exposure, report that negative result; consider more fair fresh training without reusing the heldout data. If blocked and interleaved differ materially in effective task exposure, native actions or optimizer steps, the comparison is invalid and must be corrected before promotion. Historical M2/M3/M4 negative gates remain evidence and do not prohibit new studies.

**Scope limitation:** Memory and DoorKey are two *different tasks but one MiniGrid simulator family*. Their joint success would demonstrate within-family task retention, not cross-domain transfer to Workshop, XLand, software workflows, or robotics. A later independent generality gate still requires unrelated task families and correct physical outcomes. This pilot does not train on real-world data or claim open-ended autonomous skill discovery.
