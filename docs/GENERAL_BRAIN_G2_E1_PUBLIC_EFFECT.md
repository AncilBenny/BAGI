# G2-E1 — Public-only learned action-effect prediction (preregistration)

**Status: design frozen before native collection, model fitting, or evaluation.** This is a bounded predictive-capability gate, not an autonomous policy improvement, new architecture, cross-domain weight transfer, or a claim of AGI. It must not be described as a successful experiment until an independently audited native artifact exists.

## Research question and reuse decision

The independently verified G2-D3 and D4 experiments (runs `40135565521` and `40136271815`) show that a public-observation stagnation override suppresses long repeated-command plateaus and increases genuine physical completions from 9/56 to 13/56 across the two paired layout sets. This is a small, nonrobust signal. An unchanged public image/heading does **not** establish a physically ineffective action; the override learns no outcome model. D2 further shows missed target discovery, approach, and facing opportunities.

**Open BAGI-specific question:** Can a lightweight, *learned* action-conditioned predictor anticipate a change in the next **public** observation from legal current observation and candidate action, better than information-matched controls, on disjoint environment trajectories? This is a prerequisite for testing learned recovery or belief-based planning, not proof of them.

Reuse Sutton's Dyna principle (1991, DOI 10.1145/122344.122377), established supervised binary logistic prediction with existing PyTorch (`torch.nn.Linear`, `BCEWithLogitsLoss`), the repository's `bagi/models/world_model.py` and `train_world_model.py` as reference interfaces, native `WorkshopEnv`, official XLand-MiniGrid 0.9.3, and the checksum-verified published `imitation.BC` source policies. **Do not** invent a recurrent architecture, port Dreamer, load unsafe pickles, or add a new package. The existing Workshop world model uses a transition-random split vulnerable to duplicate trajectories; this study instead groups data by environment layout and reports exact duplicates.

## Exact prospective data and budgets

- **XLand**: original native `XLand-MiniGrid-R1-9x9` with existing public 115-feature image/heading/goal/rules/**four actually executed** action histories. TRAIN layout seeds **11900–11914** (15); TEST layout seeds **12000–12009** (10). Never replace a failed/ineligible layout. Source skills `hold`, `near`, `putdown` only; **no** heldout composition teacher data. Frozen upstream BC behavior policies with original model seeds **17, 29**, reconstructed from existing SHA-verified numeric TRAIN artifacts, and a separately seeded **uniform-random native-action** behavior control. Two behavior conditions x two model seeds x three tasks x 25 layouts = **300 episodes**, cap **20** actual native actions each, **at most 6,000** real XLand interactions. The random arm's two RNG streams must be distinct and documented; both arms update the last-four-action history from what was really executed. There are **zero** new teacher queries, no training of the behavior policies, and no counterfactual/discarded simulator calls.
- **Workshop**: existing 9x9, 5x5-public-view native `WorkshopEnv`, `default` geometry for TRAIN and `mirror_x` geometry for TEST, fixed reset conventions. Two behavior sources: uniform-random native actions and the already published G1 public-switch-oriented **fixed script** as a collection fixture (not a learned Workshop policy). Ten episodes per behavior per geometry, cap **20** native actions each = **at most 800** Workshop interactions. Repeated identical script trajectories must be hashed/deduplicated in reporting; they are **not** independent samples. One mirrored test geometry is weak external validity, not evidence of Workshop layout generalization or learned skill transfer.
- Total native collection/evaluation budget **<=6,800** actual simulator actions, separately report XLand TRAIN/TEST and Workshop TRAIN/TEST, native early terminations, public-change positives, source-episode counts and duplicates. No secret, paid, deployment, or branch changes beyond the protected research branch. A single pinned CPU workflow may be proposed only after contract tests pass. Save safe numeric NPZ (`allow_pickle=False`) or JSON; never serialize/load arbitrary objects.

## Task-independent target and strict information boundary

For each actual transition `(o_t, a_t, public_reward_t, o_(t+1))`, label `y_t = 1` if and only if the **public observation signature** changes after executing `a_t`. In XLand compare the legal 115-float vectors **excluding only the last 28 executed-action-history bits**; in Workshop compare the native 5x5 public observation. All comparisons must be exact and deterministic after validating dtype, width, finite values and action legality. The target is *observable change*, **not** hidden-state change, physical pickup/drop, or native reward. Keep public reward and native terminal events as separate descriptive fields; do not use future reward or `o_(t+1)` as predictor input.

Fit the same standard logistic head to `[current public features, one-hot candidate native action]` separately in each domain (domain-specific input encoders, **no shared learned weights or cross-domain transfer claim**). Compare: (A) action-conditioned logistic; (B) **same-width, same-parameter, same-initialization/optimizer/epochs** logistic trained with actions deterministically shuffled *within each TRAIN episode*; (C) Laplace-smoothed TRAIN-only action-frequency predictor; (D) constant TRAIN-positive-rate predictor. Predictor initialization seeds **17 and 29**, exactly **20 epochs**, Adam learning rate **0.001**, batch size **64**, BCE loss, no hyperparameter tuning or threshold selection from TEST. Training uses TRAIN episodes only; TEST is never used to fit, normalize, choose thresholds, calibrate, or stop. If positive or negative TRAIN labels are absent in a domain/behavior, **fail closed** and report the prevalence rather than fabricate a trained effect model.

Evaluator-only native state can record hidden position/pocket/grid/door changes **after** the action, strictly for an audit of `public unchanged, hidden changed` disagreements. Never pass it to the actor, predictor, loss, or intervention. The predictor's output is a probability of *visible change*, not a claim that an action was a physical no-op.

## Evaluation and promotion gate

Report per-domain, per-model seed and per-behavior heldout **Brier score**, log loss, prevalence, positive-class precision/recall at frozen threshold 0.5, ten-bin expected calibration error, false-positive and false-negative counts, and the proportion of publicly unchanged transitions that nevertheless had evaluator-only hidden changes. Bootstrap Brier differences **by complete episode** (not by correlated transitions); Workshop's one heldout geometry prevents a layout-level uncertainty claim. Check for train/test layout overlap, repeated trajectories, actual action-history correctness, and no teacher labels.

The primary comparison is action-conditioned (A) versus same-capacity shuffled-action (B), with action-rate (C) and constant (D) baselines. A positive result requires lower heldout Brier for (A) than both (B) and (C) **for both XLand model seeds** and a consistent direction on the mirrored Workshop test; report paired episode-bootstrap uncertainty and never assert significance if it includes zero. An improvement only on duplicate scripted Workshop trajectories, only one XLand model seed, or only common unchanged observations is **insufficient**. If public changes are not learnably predictable, report a negative/inconclusive gate and inspect TRAIN coverage, observation aliasing and class imbalance rather than posthoc retune.

**STOP after this predictive gate.** No new policy intervention, on-policy teacher labels, task-specific BLUE logic, or additional sweep in the same iteration. Only a subsequent preregistered study may compare learned effect-guided recovery with frozen action selection at matched native steps, and must use **independently learned Workshop policies** before claiming cross-domain learned-agent utility. Physical BLUE pickup→later effective drop→final adjacency+native reward remains evaluator-only for any future XLand manipulation claim.
