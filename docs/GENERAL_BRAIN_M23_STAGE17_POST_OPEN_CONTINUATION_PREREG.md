## Scientific mechanism, primary control and causal scope

Stage16 treatment learned significantly more DoorKey strict goals (24/120 vs matched 8/120) and opened many more doors (43 vs 9 observed effective-door-open episodes), yet was far below the public actor and often did not finish after opening. We observed this pattern on already-opened Stage16 MONITOR layouts and **will not use those layout seeds for any Stage17 model fitting or choice of treatment scale**. Sequential imitation suffers compounding on-policy distribution shift, illustrated by Ross, Gordon & Bagnell (2011), https://arxiv.org/abs/1011.0686 . These results motivate a prospective, narrower test of end-of-task continuation, *not* an assumption that a teacher action or a reward is a physical event.

Two fitted arms, same teacher-executed training episodes and same public recurrent model:
- `interaction_context` (control): exact Stage16 training principle, sqrt-inverse frequency bounded class-weighted native action CE, with 4x token emphasis in within-episode fixed windows [i-3,i+2] around *actually executed* native action 3/pickup or 5/toggle. These actions are **candidates**, not proven effects.
- `post_open_continuation` (treatment): same base 4x windows, but additionally emphasize each **subsequent** native teacher action after the first **publicly witnessed real open-door transition** in that episode at factor **4x**; never multiply overlapping weights over 4x. Door opening is detected *only* from the public before-and-after `obs["image"]` for a **genuinely executed** toggle (action5) with the same public visible door cell changing state from 1=closed or 2=locked to 0=open. No world-state/oracle information may enter this detection. `obs["image"]` is 7x7x3 encoded [object, color, state], as documented at https://minigrid.farama.org/environments/minigrid/DoorKeyEnv/ . The detector is run on TRAIN source actor public observation pairs only. No extra phase feature is added to learned-policy inputs or to learned MONITOR control. If no witnessed open transition, treatment matches control exactly for that source episode. Fetch has no DoorKey post-open phase, so its teacher labels retain identical Stage16 base weighting across arms.

## Registered outcome rule and statistical uncertainty

- Main paired physical contrast: `post_open_continuation` minus `interaction_context` on the 240 physical MONITOR episodes per arm. Require absolute gain >=**+12/240**, DoorKey gain >=**+12/120**, Fetch gain >=**−4/120** (do not claim Fetch gain if it is a loss), DoorKey strict goals >=**16/120**, and strictly positive DoorKey gain in at least **2/3** independently initialized model seeds.
- Matched action-nonvacuity: full actually executed native action SHA256 paths differ for >=16/40 paired layouts in **both** source tasks for >=2 model seeds. If this distinctness fails, registered decision **INSUFFICIENT** even if aggregate success rates differ, to avoid attributing a numerical gain to behaviorally identical policies. Note: treatment-specific public episode annotations are TRAIN-only; independent MONITOR traces must be newly executed.
- Bootstrap uncertainty: 20,000 prespecified paired seed/task-stratified draws with three model seeds resampled per source task with replacement, 40 paired layouts resampled per seed, deterministic RNG **231701**; central empirical 2.5/97.5 percentiles of total full-goal treatment-minus-control. Require 95% lower bound **strictly above zero** for registered PASS.
- Actor competence gate: treatment total full goals must be >= `3 × teacher once-measured total strict goals − 24` over 240 learned MONITOR episodes. This arithmetic is a margin against a **once-measured** source actor (80 episodes) and is not 3 statistically independent teacher replications. Without this, precommitted physical composite **FAIL**, regardless of whether relative improvements or confidence conditions pass.
- Final decision **PASS** requires all preregistered numeric, distinctness, bootstrap and actor competence criteria. **INSUFFICIENT** if action distinctness criterion fails; otherwise **FAIL** if any numerical/statistical/competence criterion fails. Report all favorable and unfavorable checks without changing this rule after seeing any MONITOR data.
