## Frozen H-M4 and outcomes

**H-M4:** On *new*, independent MemoryS7 episodes, recurrent policy success under repeated *sampled* actions exceeds its deterministic success by at least **0.25 absolute**, separately in both M3 recurrent initializations; the same contrast for action4 PPO serves as a nonrecurrent control. This concerns action-selection behavior on the frozen policy, not recurrent credit assignment or memory usefulness.

- Freeze **all eight M3 policies** (arms reactive/action4/frame4/recurrent, model seeds 37/53), training steps, model weights and policy observation contracts. No training on M4 episodes, no model selection by evaluation and zero new optimizer updates.
- NEW untouched MemoryS7 evaluation layout seeds **98001–98012** and MemoryS13Random zero-shot transfer seeds **99001–99012**; previously used M1/M2/M3 held-out seeds are excluded. For each (policy, task, layout), run **one deterministic** episode and **five independent, reproducibly RNG-seeded sampled** episodes. Every rollout begins from the same native reset state for that layout; recurrent hidden state must reset via `episode_start=True`, then be carried only within its own episode. Never carry history across episodes or use a private state in the policy.
- Fixed scoring: a goal requires actual native termination and strictly positive reward; record native reward separately, including wrong-terminal zero-reward outcomes. Cap each episode at the existing 120 native actions. Preserve absolute action counts, reset counts, acted action frequencies, termination/truncation, model/policy source, RNG seed mapping and elapsed time. Sampled successes share a layout and are **not** five statistically independent test layouts.
- Reproducible sampled-action RNG: for each arm/seed/task/layout/replicate, explicitly store the complete RNG seed and reset Torch/NumPy random state as appropriate. Use a public deterministic mapping derived only from registered indices, not scored episodes. Keep model and environment randomness distinct. No online tuning on evaluation episodes.
- Expected maximum, **not actual actions**: 8 frozen policies × 2 tasks × 12 layouts × (1 deterministic + 5 sampled) × 120 = **138,240** evaluation native actions. Actual count must be obtained from the executed runner; this is a per-experiment comparison specification, NOT a custom daily/runtime/platform quota.
- Primary contrast: for **each** recurrent seed, compute sampled success proportion over five draws × 12 layouts minus deterministic success proportion over 12 layouts, and require >=0.25 separately for both seeds. Cluster uncertainty by layout, show per-seed results and control arm differences, and do not pool stochastic draws as if they are independent environments. Secondary: the same contrast for transfer and the three nonrecurrent controls, per-action choice statistics, and size-transfer failure types. If the primary contrast fails, reject H-M4; if it passes, only an action-sampling effect on this task is supported. Do not infer episodic memory content without a separate causal ablation.
- Unit/contract tests before running: synthetic checkpoint shape/dtype/hash rejection; identical deterministic replay; independent stochastic seed reproducibility; correct recurrent state reset/carry; no private observations; native score requires reward+termination; counter accounting after interruption. Use existing serialized BAGI research workflow or extend its registered study mode after tested source-only changes and exact-HEAD push+PR CI, not a new workflow, schedule or competing writer. Keep outputs in ignored `runs/m4_frozen_policy/`, all checkpoint bytes out of Git.

## Scope and stopping rule

The old M3 artifact is *cached source evidence*, not a newly fitted model; M4 evaluation is **not executed** by this preregistration. If M3 numeric checkpoints cannot be accurately restored and their deterministic behavior replayed on frozen M3 reference seeds (verification-only, excluded from M4 denominators), HOLD M4 and fix restoration before touching the new evaluation layouts. Replaying past seeds is a loader check, not an independent new result. Preserve all M1/M2/M3 independent denominators untouched.

The next higher-level BAGI question remains task-independent continual adaptation: transfer and retention across *distinct* public-observation task families, including real acted effects, cross-task performance and forgetting. MiniGrid Memory alone cannot meet it. Workshop and XLand remain diagnostics until independently verified native task outcomes exist. Future fitted models should start only when this diagnostic identifies an actionable explanation, with explicit replay/retention controls and separate test splits.
