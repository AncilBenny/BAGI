## Reuse, objective, and limitation

Official Farama MiniGrid DoorKey 6x6 and 8x8 provide seven native actions: pickup3, toggle5, and public 7x7x3 image/heading/mission. Source: https://minigrid.farama.org/main/environments/minigrid/DoorKeyEnv/ . Standard finite-memory control is motivated by Kaelbling, Littman and Cassandra 1998 (https://doi.org/10.1016/S0004-3702(98)00023-X), but the present controller is a HAND-SPECIFIED reference, not a learned POMDP, meta-learner, belief estimator or skill discovery. Reuse BAGI NativeDoorKeyAudit + EpisodeFunnel for external simulator-private outcome verification; never include that private data in action selection, memory updates, reward or model inputs. No optimizer or novel method is introduced.

**Open question:** before fitting a meaningful learned key/door precondition predictor, can a public-only exploration/finite-action-memory controller create sufficiently many REAL effective physical pickups, valid locked-door opportunities and door openings compared with public-reactive and uniform-action baselines? Treat coverage as a prerequisite rather than a learning result.

## Frozen baseline and physical evaluation

Same predeclared layout seeds under three separately seeded action controllers: uniform random native0–6; a public-reactive controller (pickup when a key is directly visible ahead; at a visibly locked door toggle with probability0.5; otherwise navigate using public front occupancy with 0.7 forward probability); and a one-bit public-memory controller with the same navigation, which toggles a visibly locked door only after its OWN executed pickup made a publicly visible front key disappear. No private state, external physical audit or reward can influence an action. Reactive and memory trajectories differ, so positive comparisons are **not isolated causal proof of memory**.

Train-only diagnostics: DoorKey6x6 layouts 171001–171024 and DoorKey8x8 181001–181024. Independent final: 6x6 172001–172036 and 8x8 182001–182036. Native horizon256. All three modes act for each layout; actual interaction count depends on native episode end. After every real action, external evaluator counts true key possession, valid locked-door-facing-with-key opportunities, actual toggle attempts, effective key pickups/door openings and full pickup→door→native rewarded goal temporal chain separately from reward. Compare public evidence memory with true physical key possession **only in evaluator**, never the actor. Preserve episode-level event counts and all seven actual native-action histograms. Final layouts are not used for tuning or model selection. Distinct DoorKey sizes are related tasks, not unrelated-domain transfer.

**Primary preregistered pilot:** in independent final each size has at least four effective pickup episodes under public-memory; public-memory must have no fewer physically effective door-opening episodes than reactive within either size and at least **two additional pooled** opening episodes. Secondary invalid toggle/action counts and physical goal comparisons to uniform native random. If pickup coverage is absent, report signal insufficiency; no artificial quota on later training.

**Why no fitting yet:** M12 demonstrated the unresolved lack of native physically positive interaction examples. This study establishes the adequacy of a public-only acquisition baseline for future training, rather than spending optimization on near-all-negative random data. This per-study fixed episode split is a controlled experimental design, NOT a daily training ceiling or ban on fresh fits in later trials.
