## One falsifiable hypothesis

**Question:** does reducing numeric input magnitude *during fresh PPO training* improve frozen stochastic **observation-conditioned navigation** relative to matched raw inputs, while keeping the source public information, action space, network, reward, seed streams, and training steps identical?

**Rival explanations:** raw Tanh saturation may not be the limiting factor; the task may be solved by a generally useful state-independent forward-heavy action distribution, or public partial observations may alias important states. If activation sensitivity changes but TEST outcome or the live-vs-stale gap does not improve, **STOP input-scale hypothesis** rather than sweeping factors/architectures on the same TEST.

## Frozen source, task, learners, data and interaction ceiling

- Only one existing diversity-screened MiniGrid task: **`MiniGrid-Empty-Random-6x6-v0`**, native sparse goal reward and 144-step cap, native 7 discrete actions. No Workshop/BLUE-specific policy logic or other task. Exactly two model initialization seeds **17 and 29**. Each seed trains one model under each of two input arms, **RAW** and **SCALED**.
- Raw public input: **147 float32 values numerically identical** to `ImgObsWrapper` + `FlattenObservation` categorical codes, with a float32 1-D Box bounded 0..10. Scaled: the **same 147 values divided by 10.0** with Box 0..1. Both satisfy exactly the same public data boundary; no new features, mission, full grid, direction, absolute position, hidden key state, history, checkpoint load, change of stochastic action temperature, reward shaping, or ensemble. The sole controlled actor-input change is numerical magnitude; both inputs are float32 to avoid confounding with dtype.
- Identical maintained SB3 **PPO 2.9.0** `MlpPolicy`, CPU single environment, `n_steps=128`, `batch_size=64`, `n_epochs=2`, `gamma=.99`, learning rate `3e-4`, `ent_coef=.01`, policy and value networks `[64,64]` Tanh. Assert exact identical initial policy parameter values for RAW/SCALED of each model seed; no pretrained weights or teacher. **Exactly 16,384 genuine native TRAIN actions per model** = **65,536** TRAIN actions. Seeds reset explicitly on every episode starting `2,000,000 + model_seed_index * 100,000 + episode_index` (same stream in the RAW and SCALED arms), with per-step public/native reward/termination/action evidence archived. Different learned policies may terminate at different times and thus consume different numbers of reset seeds; this is not a change to the registered seed stream.
- Evaluate *frozen* networks with **the original learned categorical stochastic policy**; no optimizer during evaluation. Two feedback conditions per trained network on the SAME physical reset seed: `live` (current public image) and `stale` (first public image held fixed, real world evolves). Pair original **per-episode sampling seed** across scale and feedback conditions as `29,000,000 + model_seed_index * 100,000 + test_reset_seed - 29000`. The stochastic policy and native environment then evolve freely. Save both actual-public and actor-supplied public arrays in numeric-only NPZ, plus each real action, reward, termination, and truncation. Evaluator-only full-grid SHA256, position and heading are used **only to check reset parity/diversity**, never policy input, reward or action choice.
- **Exactly 16 fresh test seeds `29000..29015`** (never touched by P0 seeds21000..21015; P1 seeds26000..26009; P2 seeds27000..27009; P3 seeds28000..28015). Match 4 observation/feedback arms (raw live, raw stale, scaled live, scaled stale) for both original model seeds. Each seed must have **at least 12 distinct physical resets of16**; scores are separately reported per seed and paired-condition. No replacement/resampling of ineligible starts.
- **IMPORTANT arithmetic correction before a native run:** Earlier P4 offline note mentioned 65,536 TRAIN +9,216 TEST =74,752 while also recommending 16 starts. That 9,216 figure would require **only eight** eval starts. At the **frozen 16** selected here, exact maximum is `2 seeds × 2 input arms × 2 feedback arms × 16 starts × 144 native steps = 18,432 TEST`, hence **65,536 + 18,432 = 83,968 total real native actions MAX**. Any natural native termination reduces executed actions. This correction is preregistered before any P4 training/heldout evaluation, not an after-the-fact budget expansion. No test-time simulator probes, uncounted normalization steps, discarded action branches or extra tasks. Zero teachers and secrets.

## Preregistered performance gate and reporting

Each model seed is scored **independently**. A *descriptive candidate feedback improvement* for SCALED requires (i) matched initial network parameters, seed streams and 12+ physically distinct TEST starts; (ii) actual rewarded TRAIN goal in BOTH models; (iii) **SCALED live ≥8/16 native goal completions**, at least as many as RAW live; (iv) **SCALED live−stale ≥3/16** AND strictly larger than RAW live−stale; and (v) **at most one paired SCALED live regression** relative to SCALED stale. These **must hold for BOTH seeds** to pass. Native goal = upstream termination AND positive native task reward; intermediate movement/action counts and training-only activation saturation are not goals.

A pass only motivates an independent separately registered confirmation. It is not evidence of AGI, reusable memory, belief or cross-domain transfer. A fail is **STOP** on this input-scaling explanation—no retrain/bonus tuning against the fresh TEST, no follow-up stochastic-temperature rescue. Report separately: per-seed RAW and SCALED TRAIN-native goals, frozen TEST live/stale native completions, native action counts, paired gains/losses, initial/final Tanh saturation on TRAIN-only numeric observations (diagnostic), exact initialization hashes, and distinct physical reset hashes. Do not confuse equal TEST start numbers across model seeds with statistically independent layouts.
