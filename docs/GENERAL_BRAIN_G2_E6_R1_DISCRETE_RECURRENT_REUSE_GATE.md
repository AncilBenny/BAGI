## Primary-source reuse and negative compatibility findings (checked 2026-10-31)

1. **3RL: reuse the *principle*, not the source as a drop-in discrete agent.** Caccia et al. (CoLLA 2023, https://proceedings.mlr.press/v232/caccia23a.html) evaluated task-agnostic continual replay + recurrent RL on Meta-World/synthetic settings, not BAGI Workshop. Official Apache-2.0 source at `amazon-science/replay-based-recurrent-rl` commit `703cc6d4cd4e4149488b6dd1f979158d71c7bdd1`: `code/main.py` directly reads `env.action_space.high[0]` and `env.action_space.shape[0]`; `code/algs/SAC/sac.py` is continuous SAC. Workshop uses **four discrete actions**. The code also has optional explicit task-ID inputs (`context_id`, `context_embedding`), which must not be enabled unless the information is public and equally supplied to controls. Porting this continuous-control implementation would require a new, separately justified algorithm/adapter and dependencies (Sequoia/Meta-World/MuJoCo). No claim of current Workshop compatibility.
2. **Existing discrete recurrent reference is closer.** Ni, Eysenbach & Salakhutdinov (ICML 2022, https://proceedings.mlr.press/v162/ni22a.html) studied recurrent model-free POMDP baselines; the official MIT repository `twni2016/pomdp-baselines` commit `e7c19c32a20033d75414b29fbc466c77c211e968` documents recurrent **SAC-discrete** on CartPole-V and provides `configs/pomdp/cartpole/v/rnn.yml`. This is an *available baseline*, not proven compatible with BAGI observation, reward, episode and action contracts. Inspect/test adapters in a separately authorized study; never run unreviewed external scripts on credentialed CI.
3. **Already-integrated lightweight control is highest priority.** MIT `Stable-Baselines-Team/stable-baselines3-contrib` commit `a8af63682070df0bda9707400b2e971055600910` provides discrete `RecurrentPPO` with correctly carried `lstm_states` and `episode_start`: https://sb3-contrib.readthedocs.io/en/master/modules/ppo_recurrent.html . BAGI already imported and ran it with Farama MiniGrid and PPO; smoke `39570422800` used only 512 train steps/model and 3 eval episodes/model, 0/3 successes in four arms: too small to rank. Upstream SB3 PPO documentation explicitly recommends **simple frame stacking as a cheaper, often competitive alternative** (https://stable-baselines3.readthedocs.io/en/master/modules/ppo.html); include that negative/control baseline. No need to reimplement PPO or LSTM.
4. **Pretrained DoorKey reuse remains blocked, not solved.** REUSE-2 already verified ZIP hash and identified old SB3 1.8.0a11/legacy normalization mismatch (2835-feature FlatObs vs BAGI 147-feature ImgObs). No untrusted `PPO.load`/`VecNormalize.load` in privileged jobs; no new checkpoint load or inference. Existing Zoo recipe remains a possible trusted baseline only after compatibility/security review.

## Exact BAGI-specific gap, falsifiable hypothesis, matched controls, STOP

**Gap:** BAGI has not demonstrated episode-and-geometry-independent, action-conditioned *specific effect* information in legal public histories, nor competent continual learning. The TRAIN-only P0B source has zero goal rewards and no alternative TRAIN geometry. An off-policy recurrent learner cannot create missing positive goal supervision merely by adding memory or replay.

**One prospective hypothesis (NOT tested):** Given a *separately approved*, public-only, source-disjoint dataset with independently repeated event-positive and event-negative cases in **every required size and geometry**, a recurrent effect predictor conditioned on observations and **actually executed** actions improves event-positive recall by at least **5 absolute percentage points** versus the strongest matched reactive/finite-frame-stack/persistence/action-only/shuffled-history controls at the same prespecified false-positive-rate ceiling and without worse calibration. Compare identical TRAIN episodes, observation/action/reward information, real steps, optimizer-update counts and independent episode+geometry-disjoint test splits. Freeze preprocessing and the event definition *before* fitting. Compare a compact PyTorch GRU and/or existing recurrent method only after the gate; do not assume a model-specific positive result.

**Hard STOP:** Without repeated positive and negative outcomes per size/geometry in distinct episodes and a genuinely independent validation/test split, fit **zero** new models; do not reuse diagnostic labels as TRAIN, adjust frozen P0B gate, rerun P0B, access size13/heldout, or bypass P6/P10a STOP and P9 native HARD STOP. If this support is established by a separately authorized protocol, first verify exact-HEAD CI and full action provenance; otherwise remain HOLD. Standard MiniGrid competence benchmarks are a **different** prospective study and do not retroactively rescue P0B.
