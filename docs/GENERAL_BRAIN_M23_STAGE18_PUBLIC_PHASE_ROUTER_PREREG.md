## Why a distinct experiment

Stage17 source-only matched public-GRU results on opened MONITOR892xxx/902xxx were: control interaction_context **92/240** full goals and post_open_continuation **92/240**, paired difference **0/240**, bootstrap 95% **[−57,+55]**, decision INSUFFICIENT. The physically independent DoorKey audit recorded control **81** effective door-opening episodes with **56** strict full goals versus post-open treatment **59** opens and **59** full goals, but these are selected conditional groups and do not prove causal downstream superiority. A plausible tradeoff is that emphasizing continuation loses earlier door-reaching behavior. Rather than further tune a loss weight on the opened MONITOR, Stage18 prospectively evaluates *switching existing two learned policy types with public-only physical evidence* on entirely fresh seeds.

The [MiniGrid DoorKey environment](https://minigrid.farama.org/environments/minigrid/DoorKeyEnv/) supplies public 7×7×3 integer-encoded [object,color,state] observations; a visible door's state0=open,1=closed,2=locked. The DAgger covariate-shift literature (Ross/Gordon/Bagnell, https://arxiv.org/abs/1011.0686) cautions that an imitation policy's own trajectory differs from the expert's. We therefore explicitly test routing under actual learner-executed histories; no inference of performance from offline label accuracy.

## Three learned MONITOR arms sharing identical trained model weights

1. `interaction_context`: execute the matched learned control GRU greedily for **every** native step, with hidden reset at episode start.
2. `post_open_continuation`: execute the corresponding matched post-open-trained GRU greedily for **every** native step.
3. `public_phase_router`: at each real native step, advance BOTH already-trained GRU hidden states on the **same** current public observation and previous **actually executed** native action, even if one policy's proposed action is not selected. **Before** the first PUBLIC same-cell door state1/2→0 transition following an **actually executed** action5, select only the `interaction_context` action. **Starting at the NEXT real native action after that witnessed open**, irrevocably select only the `post_open_continuation` action for the remaining episode. The unused action proposal is **not** an environment action or label; there is exactly ONE `env.step` per real time step. Both recurrent memories are episode-bounded, never cross episodes. Never switch on an unexecuted proposed toggle, a reward, hidden oracle event or private physical audit. If no witnessed public door open, stay on the control learner.
- For Fetch, no DoorKey opening should be observed: `public_phase_router` must remain on the control learner and **produce exactly identical true executed action histories and full-goal flags to control on every paired Fetch layout/model seed**. Any mismatch is a source-integrity error (HOLD), not a gain. No task oracle enters model features; task-only decision of whether to apply DoorKey public phase routing is explicitly a **hand-engineered external study rule**, not a learned task-selection skill.
- Fresh MONITOR original public source actor measured once on each 40 layout/task=**80 actual actor episodes**, plus each of 3 learned evaluation arms ×3 model seeds×2 tasks×40 native layouts=**720 real learned episodes**, **800 actually executed MONITOR episodes**. Every policy acts without expert fallback. Independent native audit alone defines strict DoorKey full key-pickup + effective-open + goal arrival, and Fetch movement + correct mission-target pickup. Reward-positive-only Fetch excluded. Preserve all real native actions, hashes, physical events, origin/provenance and runtimes.
